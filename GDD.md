# Heartbound (рабочее название) — GDD

Мод про отношения для Minecraft: симпатия между игроками и романтические отношения игроков с мобами.

- **Версия игры:** 1.21.1 (вниз не портируем; порты вверх, например на 1.21.11, по желанию)
- **Лоадеры:** Fabric + NeoForge (мультилоадер с самого начала)
- **Язык кода:** Java 21
- **Тон:** романтика с намёком, ничего откровенного. Только взрослые персонажи, детёныши и дети-жители в систему не попадают.

---

## 1. Ядро: система симпатии

У каждой пары «существо A → существо B» есть значение симпатии `affinity` от 0 до 1000.
Хранится у существа A отдельно для каждого B (по UUID).

**Что повышает симпатию:**
- подарки (у каждого моба свой список любимых, нейтральных и нелюбимых предметов);
- время рядом (медленный прирост раз в N секунд, если B близко и вокруг нет угроз);
- защита (B убивает врага, который атаковал A, или не даёт ему навредить);
- ласка: правый клик пустой рукой по мобу (с кулдауном).

**Что понижает:**
- урон от B;
- долгое отсутствие B (очень медленный спад до порога стадии, но не ниже);
- нелюбимые подарки.

Все числа (приросты, спад, кулдауны) выносятся в конфиг и в JSON с данными.

## 2. Стадии

| Стадия | Порог | Что открывает |
|---|---|---|
| Незнакомцы | 0 | Обычное поведение |
| Знакомые | 100 | Моб не убегает, смотрит на игрока, частицы-интерес |
| Друзья | 300 | Следует за игроком по просьбе, реплики-приветствия |
| Близкие | 600 | Защищает игрока, дарит ответные подарки, тёплые реплики |
| Пара | 800 + кольцо | Предложение и принятие, общий дом, бонусы, особые реплики |

Переход в «Пару» только через предложение (см. раздел 5), а не автоматически.

## 3. Мобы первой версии (только взрослые)

- Житель (взрослый)
- Волк
- Кошка
- Лиса

Остальных (ведьма, разбойник, лама, пчела и т.д.) добавляем позже через те же данные.

Для каждого моба в JSON описывается: любимые подарки, нейтральные, нелюбимые, реплики по стадиям, скорость прироста, особые реакции.

## 4. Предметы

- **Букет** — крафт из цветов, базовый подарок, небольшой прирост симпатии.
- **Сердечный амулет** — редкий подарок, большой прирост, крафт из ценных ресурсов.
- **Кольцо обещания** — нужно для предложения. Крафт: золотой слиток и самоцвет (алмаз или изумруд). Привязывается к получателю при использовании.

Рецепты и значения задаются датапаком, чтобы их можно было править без пересборки.

## 5. Предложение и пара

**Игрок → моб:** правый клик кольцом по мобу на стадии «Близкие» и симпатии ≥ 800. Моб принимает (частицы-сердечки, звук, реплика) или отказывает (мягкая реакция, симпатия не падает).

**Игрок → игрок:** правый клик кольцом по другому игроку отправляет ему запрос; принять или отклонить можно командой `/heartbound accept|decline` или кнопкой в чате. Пара — взаимная связь, которую любой из двоих может разорвать командой `/heartbound breakup`.

**Ограничение:** у существа может быть один партнёр одновременно (конфиг, по умолчанию включено).

## 6. Жизнь в паре

**Моб-партнёр:**
- следует за игроком (режим «рядом» / «ждать дома», переключается правым кликом с шифтом);
- привязывается к кровати или точке дома (кровать, рядом с которой игрок спал вместе с ним);
- защищает игрока в бою, но не ввязывается в безнадёжные схватки;
- реагирует на возвращение после долгого отсутствия;
- иногда дарит ответные подарки.

**Игрок-партнёр:**
- небольшие бонусы, когда партнёры рядом (регенерация или скорость, настраивается);
- `/heartbound tp` — телепорт к партнёру (кулдаун и стоимость настраиваются);
- общая точка дома.

## 7. Ночь вдвоём (намёк)

Если пара вместе ложится спать (общая кровать, оба рядом), экран затемняется как при обычном сне. Утром:
- частицы-сердечки, весёлый звук, короткая тёплая реплика;
- временный бонус «Хорошее настроение» (регенерация, скорость, чуть больше опыта).

Никаких откровенных анимаций, текстов или текстур. Всё на уровне намёка.

## 8. Диалоги и реакции

Реплики показываются в чате или над головой моба. Хранятся в JSON по стадиям и событиям (встреча, подарок, спасение, возвращение, утро после ночи вдвоём и т.д.). Локализация через стандартные языковые файлы (ru_ru, en_us).

## 9. Данные и конфиг

- **Данные** (JSON/датапак): любимые подарки, реплики, пороги, рецепты.
- **Конфиг:** приросты, спад симпатии, кулдауны, лимит партнёров, бонусы пары, включение и выключение отдельных механик.

## 10. Архитектура (мультилоадер)

```
heartbound/
├── common/      # вся логика: симпатия, стадии, поведение мобов, предметы, данные
├── fabric/      # точки входа, регистрация, события, сеть, хранение под Fabric
└── neoforge/    # то же самое под NeoForge
```

Правила:
1. **В `common` всё, что можно.** Платформенный код только там, где иначе нельзя.
2. **Платформенные службы за интерфейсами** (`PlatformHelper`, `AffinityStorage`, `NetworkHelper`), реализации подгружаются через `ServiceLoader`.
3. **Чистая логика симпатии** (подсчёт, пороги, спад) без прямых вызовов Minecraft, чтобы легко тестировать и портировать.
4. **Хранение данных на сущностях:** Fabric Data Attachment API и NeoForge Data Attachments за общим интерфейсом.
5. **Данные в JSON**, а не в коде.

Рекомендуемая база: шаблон MultiLoader (маппинги Mojang), без Architectury.

## 11. Дорожная карта

1. **Каркас:** gradle мультимодульный проект, сборка Fabric и NeoForge, пустой мод запускается на обоих.
2. **Ядро симпатии:** компонент, хранение, команды отладки (`/heartbound affinity get|set`).
3. **Подарки и ласка:** предметы, прирост симпатии, реакции мобов, частицы.
4. **Стадии и диалоги:** пороги, реплики, JSON-данные.
5. **Предложение и пара:** кольцо, запросы, разрыв, лимит партнёров.
6. **Жизнь в паре:** следование, дом, защита, бонусы, телепорт.
7. **Ночь вдвоём:** затемнение, утренняя реакция, бонус.
8. **Полировка:** конфиг, локализация, текстуры, баланс, ошибки.
